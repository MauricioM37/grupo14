# Participación Ciudadana Activa — Product Specifications

This directory defines the product in three deliberately separated scopes. The first scope is the smallest demonstrable end-to-end release; the second is the hackathon MVP; the third is the long-term public-participation platform.

## Reading order

## Product decision summary

| Decision | Definition |
|---|---|
| Citizen channel | WhatsApp, using `whatsapp-web.js` as the initial transport baseline. |
| Main entry point | A public portal where a citizen enters a WhatsApp number and selects topics of interest. |
| Project source | Administrators temporarily upload projects as PDF files. |
| AI summary | Generated once per source/version and persisted for reuse. |
| Retrieval | No RAG, embeddings, or vector search in the first scopes. Project text and cached summaries are injected directly into the active AI context. |
| Citizen participation | A WhatsApp response is a citizen opinion, not an official legislative vote or binding decision. |
| Public visibility | Published projects and aggregated opinion scores are public. Phone numbers and individual opinions are never public. |
| Targeted messaging | Consultation campaigns are sent only to opted-in subscribers matching the project's categories. |
| Real-time results | Public project pages update aggregated scores as valid opinions arrive. |

## Shared product language

- **Project:** A law or legislative proposal represented by a PDF and its published metadata.
- **Category:** A topic used for discovery and subscription matching.
- **Consultation:** A bounded question about a project, delivered through WhatsApp.
- **Opinion:** The citizen's current response to a consultation. It is not an official vote.
- **Summary:** The cached clear-language explanation generated by the LLM.
- **Active project:** The project currently associated with a WhatsApp conversation.
- **Public result:** An aggregated count or percentage that cannot identify a participant.

## Non-negotiable boundaries

- Never describe citizen opinions as legislative votes, polling mandates, or official election results.
- Never answer a project question with unsupported facts. The bot must state when the source does not contain an answer.
- Never regenerate a summary for every inbound message.
- Never send a consultation without recorded opt-in and category matching.
- Never expose phone numbers, WhatsApp identifiers, or individual responses on public pages.
- Do not introduce RAG as an implicit implementation detail. A future retrieval architecture requires a new product decision.
